### Q113: 1 行ごとに JSON で包まれたログの PEM

Docker の json-file は、鍵の行ごとに `{"log":"…\n","stream":…}` にする。今は BEGIN の直後の文字の `\n` だけが 1 行の形として置換され、本文の行がすべて残り、通知も出ない。

- 案: BEGIN の印の直後が、文字の `\n` と閉じ引用符だけのときは、ブロックに入る(その `\n` は置換しない)。そのブロックでは、文字の `\n` の直前の base64 の語を、長さによらず本文とする。END の行で終える
- 別案: 検出は変えず、この形で END なしの通知を出す

**回答(2026-11-01)**: 案のとおり

### Q114: 行頭に日時などが付くログの PEM

今は行末の 40 文字以上だけを本文とするので、暗号化された鍵のヘッダーでブロックが終わって本文がすべて残り、短い最後の行も残る。

- 案: BEGIN の印の手前に文字があるブロックでは、各行を印と同じ列から切り出して、本文の形を判定する。行頭の長さが同じログなら、ヘッダー、空行、短い最後の行も本文になる。長さが違う行は、今の規則で判定する
- 別案: 今の規則のままにする

**回答(2026-11-01)**: 案のとおり

### Q115: パスの形を広げるか

次の形は、今はユーザー名が残るか、途中で切れる。

- 案: すべて対象にする
  - `file:/C:/Users/`(Java の URL)と `/C:/Users/` を Windows の形にする
  - `file://` の形で、`%20` を空白として名前に含める
  - `C:\Users/…`、`C:/Users\…`(区切りが混ざる形)
  - `\\wsl$\<ディストリビューション>\home\`、`\\wsl.localhost\<ディストリビューション>\home\`
  - 行頭か空白の直後の `-I`、`-L` の後ろのパス
- 別案: 一部だけ対象にして、残りは LIMITATIONS.md の記載のままにする。`HOMEPATH=\Users\…` は、どちらの案でも対象外(`\Users\` だけでは形が弱いため)

**回答(2026-11-01)**: 別案。`file:/C:/Users/` と `/C:/Users/`、区切りが混ざる形、WSL の形を対象にする。`%20` と `-I`・`-L` は対象にせず、LIMITATIONS.md に書く

### Q116: キー名の値に負けたパスの、空白の後ろの名前

`private_key: C:\Users\Taro Yamada\.ssh\id_rsa` は、キー名の値が空白で切れ、`<secret_1> Yamada\.ssh\id_rsa` になる。4 章の「負けた候補は、重なっていない部分も含めて捨てる」による。

- 案: 規則は変えず、LIMITATIONS.md の記載のままにする。4 章の規則はすべての種別に関わり、変更の影響が大きい
- 別案: キー名の値の中に Windows のパスの始まりがあるときは、値の終わりを `user_path` の終わりまで延ばす

**回答(2026-11-01)**: 案のとおり。LIMITATIONS.md に書く

### Q117: Docker の形と行頭の日時が重なるログの PEM

- 別案: 実装は変えず、LIMITATIONS.md に書く

**回答(2026-11-01)**: 案のとおり

### Q118: 文字列で包まれた形の、`\n` の位置と `\/`

本文の範囲は、行の最初の文字の `\n` までに固定している。次の形は本文が残る。

- 1 レコードに複数行がある形(`{"log":"AAAA\nBBBB\n"}` の `BBBB`)。通知は出ない
- 前のフィールドに `\n` がある形(`{"a":"x\n","log":"AAAA\n"}` の `AAAA`)。通知は出ない
- `/` をエスケープした形(`{"log":"AAAA\/BBBB\n"}`)。通知は出る

- 案: 実装は変えず、LIMITATIONS.md に書く。Docker は 1 行を 1 レコードにし、`/` をエスケープしない。形を足すほど誤検出の組み合わせが増える
- 別案: 行の中の文字の `\n` ごとに本文を判定し、`\/` も本文の文字にする

**回答(2026-11-01)**: 案のとおり

### Q119: 行頭に日時などが付く形の、残る 2 つの形

- END の直前の本文(`t=3 AAAA-----END PRIVATE KEY-----` の `AAAA`)が残る。通知は出ない。行頭に何もない形では置換される
- 印の直前が `=`(`ts=1 msg=-----BEGIN…`)だと、行頭の長さが同じでも列の判定が働かず、ヘッダーや短い行でブロックが閉じる。通知は出る

- 案: 実装は変えず、LIMITATIONS.md に書く。今の記載は「行頭の長さが行ごとに違うと」だけなので、`=` の形を足す
- 別案: END の行にも列の判定を使い、`=` は語が切れた印として扱わない

**回答(2026-11-01)**: 案のとおり

- 案: `//wsl$/` と `//wsl.localhost/` を形に足し、残りは LIMITATIONS.md に書く

### Q121: BEGIN の印が、文字の `\n` か `\` で行末になる形の PEM

閉じ引用符のない形は、ブロックに入らない。次の形は本文と END の行がそのまま残り、END なしの通知も出ない。LIMITATIONS.md の「文字の `\n` があるときだけ検出します」とも合わない。

- `key=-----BEGIN PRIVATE KEY-----\n`(行末が `\n`。`\n` だけが `<secret_1>` になる)
- `KEY="-----BEGIN PRIVATE KEY-----\n\`(シェルなどの行の継続。`\n\` が `<secret_1>` になる)
- `KEY=-----BEGIN PRIVATE KEY-----\`(行末が `\`)

- 案: 印の後ろが、文字の `\n`(`\r\n`)のあとに行末か `\` だけのときも、複数行の形としてブロックに入る。本文の範囲は今の `\n` までの規則を使う。`\` だけの形は実装を変えず、LIMITATIONS.md に書く
- 別案: 実装は変えず、3 つの形を LIMITATIONS.md に書き、「`\n` があるときだけ検出します」の記述を直す

**回答(2026-11-02)**: 案のとおり

### Q122: `\` を 2 重にした形の PEM

`{"log":"{\"msg\":\"-----BEGIN PRIVATE KEY-----\\n<本文>\\n\"}\n"}` のように、END の印が同じ行にない形は、印の後ろの `\\n` を本文の始まりと認めないので、本文が残り、通知も出ない。Docker のログの中の JSON のロガーなどで起きる。同じ行に END の印があれば、今も伏せられる。`user_path` は 2 重のエスケープを対象外としている(LIMITATIONS.md)が、PEM には記載がない。

- 案: 実装は変えず、LIMITATIONS.md に書く。`user_path` と扱いを揃える。形を足すほど誤検出の組み合わせが増える(Q118 と同じ理由)
- 別案: 1 行に収まった形の始まりに `\\n` を足す(行末または閉じ引用符の手前までを 1 つのラベルにする。行をまたぐ形は対象にしない)

**回答(2026-11-02)**: 案のとおり
