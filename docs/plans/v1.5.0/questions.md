## #13 ホームディレクトリのユーザー名

### Q100: 種別名と、既定で有効にするか

仕様 4 章は、既定で有効にするものを「どこでも使われる技術的な値」としている。ユーザー名はクラウドに依存せず、スタックトレースのどこにでも出る。一方、既定の動作が変わり、`GET /home/dashboard` のような Web のパスも誤って伏せる。

- 案: 種別名は `user_path`。**既定で有効**(`--types default` に含める)。優先順位は `custom` の次(最後)にして、`--deny yamada` と同じ長さで重なったら `<custom_N>` にする。誤検出は LIMITATIONS.md に書く
- 別案: 既定では無効にする。既定の動作は変わらないが、`--types default,user_path` を知らない人の名前が残る

**回答(2026-11-01)**: 案のとおり。種別名は `user_path`、既定で有効。今の種別名はすべてアンダースコアで、ハイフンは使っていないので、それに揃える

### Q101: 対象の形

issue は `/home/<ユーザー>/`、`/Users/<ユーザー>/`、`C:\Users\<ユーザー>\` の 3 つ。実際のログでは、JSON のエスケープなどの形でも出る。

- 案: 3 つに加えて、`C:\\Users\\…`(JSON、Python の repr)、`C:/Users/…`、`/mnt/c/Users/…`(WSL)、`/c/Users/…`(Git Bash)、`file:///home/…` を対象にする。Windows の形は大文字・小文字を区別しない。`/home/` などの前は、行頭か、英数字・`-`・`_`・`.`・`/` 以外の文字とする(`https://example.com/home/x`、`/var/home/x` は対象外)
- 別案: issue の 3 つだけにする。JSON のログの Windows のパスは残る

**回答(2026-11-01)**: 案のとおり

### Q102: 対象外にするユーザー名

`PWD=/home/user` は、既存のテスト 3 つと仕様 9 章が「置換しない」と期待している。一般的な名前を対象外にすれば、この期待値は変わらない。

- 案: 固定の短い一覧を設ける。`user`、`ubuntu`、`ec2-user`、`debian`、`centos`、`admin`、`runner`、`node`、`vagrant`、`Administrator`、`Public`、`Default`、`Default User`、`All Users`、`Shared`、`Guest`。`/root/` は対象の形に当たらない。一覧の追加は `--allow`(ユーザー名との完全一致)で行う
- 別案: 一覧を設けず、すべて置換する。`PWD=/home/user` の既存の期待値と仕様 9 章を変えることになる

**回答(2026-11-01)**: 案のとおり。バージョンの表記(`v1` など)の除外を一度加えたが、同じ日に取り消した。想定していた `/v1/aaa/` や `/api/v1/` は、もともと対象の形でなく、除外が効くのは `/home/v1/` のようなまれな形だけのため

### Q103: ユーザー名の範囲

`C:\Users\Taro Yamada\AppData` のように、Windows のユーザー名は空白を含むことがある。日本語の名前もある。

- 案: 値は、英数字・`.`・`_`・`-`・`@`・`+` と非 ASCII のバイトの連なり。末尾の `.` は含めない。`$USER`・`*`・`<user>`・`%USERNAME%` は文字で除かれる。Windows の形だけ、次の `\`(または `/`)までが同じ行にあれば空白を含めてよい。`/home/yamada` のように、後ろに `/` がなくても対象にする
- 別案: 空白を含めない。`C:\Users\Taro Yamada\` は `Taro` だけが置換され、`Yamada` が残る

**回答(2026-11-01)**: 案のとおり

## #14 PEM の秘密鍵

### Q104: 対象と、仕様 2 章の扱い

- 案: 2 章の対象外を「複数行にまたがる値(PEM の秘密鍵を除く)」に変える。対象は、`-----BEGIN <任意の語> PRIVATE KEY-----`(`RSA`、`EC`、`DSA`、`OPENSSH`、`ENCRYPTED`、語なし)と、`-----BEGIN PGP PRIVATE KEY BLOCK-----`。`CERTIFICATE`、`PUBLIC KEY` は対象外。`secret` の一部とし、`secret` が無効なら行わない。BEGIN と END の行の印は残す
- 別案: PGP を含めない

**回答(2026-11-01)**: 案のとおり

### Q105: 鍵の本文のラベル

- 案: **行ごとに別のラベル**にする。4096 ビットの RSA で約 50 個の `<secret_N>` になり、後ろの `secret` の番号がその分ずれるが、行の数と改行コードが保たれ、`Masker`・`restore` を変えずに 1 バイトも違わずに戻せる。ブロックの長さに上限がなくてもメモリが増えない
- 別案: ブロック全体で 1 つのラベルにする。出力は短くなるが、行の数が変わって行番号の通知がずれ、値が改行を含むので `Engine` の「1 行の中で閉じる」前提が崩れる。END が来るまで保持するメモリの上限も要る

**回答(2026-11-01)**: 案のとおり

### Q106: END がない場合と、本文の形

`-----BEGIN … PRIVATE KEY-----` は、エラーの文章やコードにも現れる。途中で切れたログもある。一方、行の先頭に日時が付くログでは、本文の形を厳しくすると鍵が残る。

- 案: 本文の形でない行が来たら、END がなくてもブロックを終え、その行から通常の検出に戻す。stderr に行番号だけを通知する(終了コードは変えない)。本文の形は、次のどれか。行全体が base64 の文字(前後の空白を除く)、`名前: 値` のヘッダー、空行、置換済みの形、行末の語が base64 の文字 40 文字以上(行頭に日時などがある形。その語だけを置換する)。ブロックの状態は、入力ごとに戻す
- 別案: END がなければ、入力の終わりまで伏せる。残る心配はないが、文章に印が現れただけで、後ろのログがすべて消える

**回答(2026-11-01)**: 案のとおり

### Q107: 1 行に収まった形

`{"pem": "-----BEGIN…\n…"}`(`\n` が文字)と、`KEY=-----BEGIN … ----- QUJD… -----END … -----`(改行を空白にした形)は、今そのまま残る。issue には書かれていないが、現実にありうる形で値が残るので、[振り分けの基準](../../DEVELOPMENT.md)では直す対象になる。

- 案: v1.5.0 で対応する。同じ行に END があれば、BEGIN の印と END の印の間を 1 つの `<secret_N>` にする。END がなければ、BEGIN の印の直後が `\n`・空白・base64 の文字のときだけ、行末または閉じ引用符の手前までを置換する(`"-----BEGIN PRIVATE KEY-----"` だけの行は置換しない)。キー名ベースで値全体を置換する形は、今のまま
- 別案: 複数行の形だけにして、LIMITATIONS.md に書く

**回答(2026-11-01)**: 案のとおり

## #16 確認のモード

### Q108: `--review` の出力先と、色の条件

issue の論点は、stdout か stderr か、色の条件、「stderr に値を出さない」方針との関係。

- 案: mask の出力を **stdout** に、置換した箇所に色を付けて出す。`mask` のサブコマンドだけのオプションで、`--mode hash` でも使える。出力の中身は通常の mask の出力と同じ範囲なので、新しく見せる値はなく、stderr の方針にも触れない。`--review` は確認専用と明示し、出力先が端末でなくても色を付ける(`| less -R` で見るため)。環境変数 `NO_COLOR` があれば付けない。出力の制御文字は `^[` のように見える形にする(ログの中の制御文字で、表示を隠せないように)。`-o`、`--out-dir` との同時指定はエラーにする
- 別案 1: 通常の出力は stdout のままにして、確認用の表示を stderr に出す。`| pbcopy` と 1 回で両方できるが、置換されなかった値が stderr に出るので、今の方針の例外が要る
- 別案 2: stdout に出し、端末のときだけ色を付ける。`| less -R` で色が付かないので、`--color` がもう 1 つ要る

**回答(2026-11-01)**: 案のとおり

### Q109: 置換しなかったが怪しい語を知らせるか

ラベルは色がなくても読める。`--review` が確認の助けになるのは、残った値に気づけるときなので、この機能は同じ版に入れる価値がある。ただし #22(エントロピーによる判定)と重なる。

- 案: v1.5.0 に入れる。`--review` のときだけ、置換しなかった部分の、英数字・`+`・`=`・`_`・`-` の 20 文字以上の並びで、英字と数字の両方を含むものに別の色を付ける。最後に、件数と行番号だけを stderr に出す。置換の結果と終了コードは変えない。誤検出が多ければ、段階 4 で規則を調整する
- 別案: 色付けだけにして、怪しい語は #22 に回す

**回答(2026-11-01)**: 案のとおり

## #19 ファイルごとの書き出し

### Q110: 出力ファイルの名前と、`-o` との関係

`logs/a/app.log logs/b/app.log` のように、ファイル名が重なることがある。絶対パスや `..` を含むパスもそのままつなげない。

- 案: 入力の**共通の親ディレクトリからの相対パス**で書き出す(`logs/a/app.log logs/b/app.log` → `DIR/a/app.log`、`DIR/b/app.log`。1 ファイルなら `DIR/app.log`)。絶対パスと `..` も同じ規則で扱える。`DIR` と途中のディレクトリは作る。同じファイルの 2 回指定、`-`(stdin)、FILE なし、ディレクトリの指定、`-o` との同時指定はエラーにする。ディレクトリを再帰的にたどらない(`find` などで渡す)
- 別案: ファイル名だけで書き出し、重なればエラーにする。規則は簡単だが、`*/app.log` のような指定が使えない

**回答(2026-11-01)**: 案のとおり

### Q111: 既存のファイルの上書き

`-o` は上書きする。`--out-dir` で上書きを許すと、前回と入力が違うときに、連番の違うファイルが同じディレクトリに混ざる(同じラベルが別の値を指す)。

- 案: 書き出し先に 1 つでも既存のファイルがあれば、**何も書かずにエラー**にする。入力のディレクトリを指定して元のファイルを消す事故も防げる。やり直すときは、利用者がディレクトリを消す。途中でエラーになったら、今回書いたファイルを消す。新しいファイルとディレクトリの権限は 0600・0700 にする(入力より広げないため)
- 別案 1: `-o` と同じく上書きする。再実行は簡単だが、前回のファイルが混ざる
- 別案 2: エラーにしたうえで、`--force` を加える。オプションが 1 つ増える

**回答(2026-11-01)**: 案のとおり

### Q113: 1 行ごとに JSON で包まれたログの PEM

Docker の json-file は、鍵の行ごとに `{"log":"…\n","stream":…}` にする。今は BEGIN の直後の文字の `\n` だけが 1 行の形として置換され、本文の行がすべて残り、通知も出ない。

- 案: BEGIN の印の直後が、文字の `\n` と閉じ引用符だけのときは、ブロックに入る(その `\n` は置換しない)。そのブロックでは、文字の `\n` の直前の base64 の語を、長さによらず本文とする。END の行で終える
- 別案: 検出は変えず、この形で END なしの通知を出す

**回答(2026-11-01)**: 案のとおり

### Q114: 行頭に日時などが付くログの PEM

今は行末の 40 文字以上だけを本文とするので、暗号化された鍵のヘッダーでブロックが終わって本文がすべて残り、短い最後の行も残る。

- 案: BEGIN の印の手前に文字があるブロックでは、各行を印と同じ列から切り出して、本文の形を判定する。行頭の長さが同じログなら、ヘッダー、空行、短い最後の行も本文になる。長さが違う行は、今の規則で判定する
- 別案: 今の規則のままにする

**回答(2026-11-01)**: 案のとおり

### Q115: パスの形を広げるか

次の形は、今はユーザー名が残るか、途中で切れる。

- 案: すべて対象にする

  - `file://` の形で、`%20` を空白として名前に含める

### Q118: 文字列で包まれた形の、`\n` の位置と `\/`

本文の範囲は、行の最初の文字の `\n` までに固定している。次の形は本文が残る。

- 1 レコードに複数行がある形(`{"log":"AAAA\nBBBB\n"}` の `BBBB`)。通知は出ない
- 前のフィールドに `\n` がある形(`{"a":"x\n","log":"AAAA\n"}` の `AAAA`)。通知は出ない
- `/` をエスケープした形(`{"log":"AAAA\/BBBB\n"}`)。通知は出る

- 案: 実装は変えず、LIMITATIONS.md に書く。Docker は 1 行を 1 レコードにし、`/` をエスケープしない。形を足すほど誤検出の組み合わせが増える
- 別案: 行の中の文字の `\n` ごとに本文を判定し、`\/` も本文の文字にする

**回答(2026-11-01)**: 案のとおり

### Q119: 行頭に日時などが付く形の、残る 2 つの形

- END の直前の本文(`t=3 AAAA-----END PRIVATE KEY-----` の `AAAA`)が残る。通知は出ない。行頭に何もない形では置換される
- 印の直前が `=`(`ts=1 msg=-----BEGIN…`)だと、行頭の長さが同じでも列の判定が働かず、ヘッダーや短い行でブロックが閉じる。通知は出る

- 案: 実装は変えず、LIMITATIONS.md に書く。今の記載は「行頭の長さが行ごとに違うと」だけなので、`=` の形を足す
- 別案: END の行にも列の判定を使い、`=` は語が切れた印として扱わない

**回答(2026-11-01)**: 案のとおり
