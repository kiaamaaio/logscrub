### `--deny`(#7)

- **Q71(種別名)** `custom`。ラベルは `<custom_1>`、hash は `custom_<hex>`
  - 案: `custom`(issue の案)。将来の `--pattern`(#18)も同じ種別にまとめられる。仕様 4 章の「`custom` 正規表現」の行は、#18 への参照に直す
- **Q72(大文字・小文字)** 案: 区別しない(ASCII のみ)。`Acme`・`ACME` は `--deny acme` で一致する
  - 理由: ログには同じ語が綴りを変えて現れ、見逃しを減らす方針に合う(仕様 7 章)
  - 綴りが違えば別のラベルになる(`<custom_1>` と `<custom_2>`)。同じ値の判定はバイト列のまま(Q3)で、`restore` で 1 バイトも違わずに戻すため
  - 全角の英字(`Ａｃｍｅ`)は一致しない。LIMITATIONS.md に書く
- **Q73(語の境目)** 案: 見る。**語の端が ASCII 英数字で、その外側の文字も ASCII 英数字なら、一致としない**
  - `acme` は `acmerica`・`AcmeCorp` に一致しない。`acme-prod`・`acme_prod`・`acme.internal`・`Acmeの` には一致する(`_` は境目。ここを語の一部とすると、社名が残るため)
  - 語の端が非 ASCII なら、境目を見ない(`アクメ` は `株式会社アクメの` に一致する)
  - 代わりの案は「境目を見ない」。見逃しは減るが、`--deny ace` が `replace` を壊す。`AcmeCorp` を伏せたい場合は、その語も指定してもらう(LIMITATIONS.md に書く)
- **Q74(重なりの優先度)** 案: 規則は変えない。長いほうが勝ち、同じ長さなら優先順位で決める。順位は `… → aws_host → host → custom`
  - 語より長い値に含まれる場合は、その値全体が置換されるので語も隠れる(`taro@acme.co.jp` → `<email_1>`)
  - 語を優先する例外を入れると、長い値の残りが出力に残るため、入れない
  - 語が置換済みの形に含まれる場合(`--deny email` と `<email_1>`)は、保護範囲のほうが長いので再置換されない
- **Q75(`--types` との関係)** 案: `--deny`・`--deny-file` を指定すると `custom` が加わり、`--domain` を指定すると `host` が加わる(`--uuid-versions` と同じ)
  - `--types email --deny acme` は email と語が対象。`--types custom --deny acme` は語だけが対象
  - 語の指定がないのに `--types custom`・`--types host` を指定した場合は、エラーにする(何も置換されないまま気づかないのを防ぐため)。`default`・`cloud` には含めない
- **Q76(語の指定の書式)** 案:
  - `--deny VALUE`: 値をそのまま 1 語にする。空の値と、改行を含む値はエラー
  - `--deny-file FILE`: 複数回指定できる。1 行 1 語。CRLF・先頭の UTF-8 BOM を除き、前後の空白を除く。空行と `#` で始まる行は無視する(Windows の配布に合わせた扱い)
  - 語が 1 つもないファイルはエラーにしない(空の一覧を運用で使えるように)。この場合は `custom` も加えない
  - 語の順と重複は、連番に影響しない(連番は入力に現れた順)
  - `--deny` の値はコマンドの履歴やプロセスの一覧に残る。LIMITATIONS.md に書き、`--deny-file` を勧める
- **Q77(`--allow` との関係)** 案: 今の仕組みのまま、`--allow` が勝つ。エラーにしない
  - `--allow` は候補の範囲との完全一致なので、`--deny acme --allow Acme` は `Acme` だけ残し、`ACME` は置換する
  - `--deny acme --allow acme-public` は効かない(候補は `acme` で、`acme-public` と一致しないため)。LIMITATIONS.md に書く

### `--domain`(#8)

- **Q78(伏せる範囲と判定)** 案: **ホスト名全体を `<host_N>` にする**。種別名は `host`
  - 理由: `aws_host` が末尾を残すのは AWS のドメインが公開の情報だからで、`--domain` のドメインは利用者が隠したいもの。`<host_N>.example.co.jp` では会社が分かる
  - 指定したドメインそのものも対象にする(`example.co.jp` → `<host_1>`)
  - 大文字・小文字を区別しない。綴りが違えば別のラベルになる(Q72 と同じ)
  - 手前の文字は英数字・`-`・`_`・`.`、非 ASCII は含めない。国際化ドメインは対象外(`xn--…` の形なら指定できる)
  - 後ろは `isHostEnd` の条件。このため `example.co.jp.evil.org` は対象外になるが、`example.co.jp-access.log`・`api.example.co.jp.log` も対象外になる(LIMITATIONS.md に書き、必要なら `--deny` を併用してもらう)
  - 値の確認: 英数字・`-`・`.` だけで、空のラベルがないこと(`https://…`・`*.example.jp`・`.example.jp` はエラー)。1 語の `--domain internal` は認める
  - メールアドレス: 特別な規則を設けない。email が有効なら全体が `<email_N>` になる(長いほうが勝つ)。email を無効にすると `taro@<host_1>` になる
  - `--email-hash local` は、3.5 節のとおり、語または指定したドメインを含むアドレスだけ `email_<hex>` にする。代わりの案は LIMITATIONS.md に書くだけにすることだが、利用者が伏せると指定した値が残るため採らない

### `--version`・配布(#10、#9)

- **Q79(`--version`)** 案: サブコマンド `version` と `--version`(`-version`)の両方を受け付ける。出力は stdout に `logscrub v1.3.0`、終了コード 0。サブコマンドの後ろの `--version` は対応しない
  - 版は `debug.ReadBuildInfo` だけで取る。`go install …@v1.3.0` もタグの位置のビルドも、これで版が出る(2 節)。`-ldflags` の仕組みは作らない
  - 開発用のビルドは `v1.0.1-0.…` のように出るが、そのままにする(`+dirty` も同様)。正しくするには `main` のタグを develop へ取り込む必要があり、ブランチの運用が変わるため
- **Q80(配布の方法)** 案: **手で実行するスクリプト**(`scripts/build-release`)でビルドし、`gh release upload` で置く。GitHub Actions は使わない
  - 理由: Release は今も手で作っている。Go の操作を Docker の中で行う決まりを保てる。ワークフローの保守と権限の管理が増えない。外部の Action に依存しない
  - 欠点: macOS で実際に動かす確認ができない。Actions の `macos-latest` なら確認できる。必要になれば、同じスクリプトを呼ぶワークフローを足せる
  - 配布物は**圧縮しないバイナリ**(`logscrub-v1.3.0-linux-amd64`、`…-windows-amd64.exe` など 6 個)と `SHA256SUMS`。`zip` が環境になく(2 節)、1 個 約 2.5MB で圧縮の利点が小さく、`curl` で取ってすぐ使えるため
  - 署名はしない。README に、macOS の Gatekeeper(ブラウザで取得した場合の `xattr -d com.apple.quarantine`)と、Windows の SmartScreen の警告を書く
  - PowerShell のパイプは文字コードを変えることがあるので、README の Windows の説明はファイルを引数で渡す形にする

### `restore`(#17)

- **Q81(認める形)** 案: 次の形だけを認める
  - `&lt;email_1&gt;`、`\<email_1\>`: **始めと終わりの両方が同じ方式で崩れているときだけ**。片方だけの `\<email_1>` は認めない(`C:\<secret_1>` の `\` が消えてしまうため)
  - Markdown の形では、`_` の `\` はあってもなくてもよい(`\<ipv4\_private\_1\>`)。Markdown の変換で実際に起きるため。issue の範囲より少し広い
  - 括りを外した `email_1` は対象外のまま(変数名などを誤って戻すおそれがあるため。issue の「決めること」への回答)
  - `&#60;`・`%3C`・`\u003c`・全角の `<` などは対象外のまま。必要になったら、同じ仕組みに足せる
  - 戻す値はエスケープしない(元の値をそのまま入れる)
  - `--mask-format` を変えた場合は、書式のリテラルから同じ規則で作る(3.6 節)。`{type}_{n}` のように括りがない書式は、もともと括りを外した形がラベルなので、`\_` の形だけが増える
  - 対応のない崩れたラベルは残し、元の形(`<email_3>`)で通知する。同じラベルの形違いは 1 件に数える
- **Q82(往復を守る)** 案: mask の出力に現れた崩れた形は、回答でも崩れたラベルとして扱わない(3.6 節)
  - 問題: 元の入力の `literal &lt;email_1&gt; here` が、別の値に書き換わる(`\<email_1\>` も同じ。段階 8 の記録を参照)。仕様 9 章の「1 バイトも違わずに戻る」と、任意の文字列を流す `FuzzRestoreRoundTrip` に反する
  - この案なら、どの入力でも往復が成り立つ。代償は、同じ形が元の入力にある場合に限り、AI が崩した同じ形も戻らないこと(LIMITATIONS.md に書き、stderr に通知する)
  - 代わりの案は `--strict` のようなオプションで切り替えることだが、既定の往復の保証が崩れるため採らない
